# STUDIO — производственный конвейер

Рендерит готовые к загрузке видео для сна: многочасовое аудио + бесшовный визуал.
Один человек, одна команда, никаких внешних сервисов во время рендера.

```bash
pip install numpy imageio-ffmpeg
./engine/build.sh --preset rain_window --mode rainglass --hours 3 --out out/rain_3h.mp4
```

## Почему аудио синтезируется, а не генерируется нейросетью

Higgsfield **не умеет** создавать музыку: инструмент `generate_audio` на этом сервере —
только синтез речи, и он прямо запрещает использовать свои музыкальные модели
(`sonilo_music`, `mirelo_text_to_audio`) вне игрового пайплайна. Поэтому музыку
для канала он дать не может — ни в каком виде.

Вместо этого `engine/sleepaudio.py` синтезирует звук с нуля средствами DSP.
Это оказалось не обходным путём, а лучшим решением для требования
«чтобы потом не создало проблем»:

| | AI-музыка (Suno и аналоги) | Этот движок |
|---|---|---|
| Авторство | Провайдер остаётся «автором», вам даётся лицензия | Произведение полностью ваше |
| Гарантия авторского права | Прямо не гарантируется | Обычное авторское право на вашу программу и её вывод |
| Защита от претензий | Отсутствует (индемнификации нет) | Претензии невозможны: нет исходного материала |
| Content ID | Риск ложных претензий | Риска нет |
| Смена условий сервиса | Может обнулить права | Не применимо |
| Стоимость за час аудио | Подписка + лимиты | 0 |
| Уникальность | Похожие генерации у тысяч каналов | Каждый рендер уникален по seed |

## Компоненты

### `engine/sleepaudio.py` — аудио

Спектрально формованный шум через оконное overlap-add БПФ: каждый сэмпл —
новый псевдослучайный материал, поэтому **в 8-часовом рендере нет ни одного
повторяющегося фрагмента**. Поверх — модели явлений: пуассоновские капли по стеклу,
медленные порывы ветра, циклы волн, аддитивные пэды с искусственной реверберацией.

Пресеты: `rain_window` `rain_pad` `brown_noise` `pink_noise` `white_noise`
`brown_rain` `ocean` `ocean_pad` `pad_only` `fireplace` `wind` `stream`

Пресеты различаются не на словах — проверено измерением 20-секундных рендеров:

| Пресет | Резких атак/с | Куртозис огибающей | Низ / Середина / Верх, дБ |
|---|---|---|---|
| `fireplace` | 6 | 4.4 | 57.7 / 35.9 / 20.2 |
| `rain_window` | 8 | 2.1 | 55.2 / 46.2 / 37.5 |
| `wind` | 2 | 2.8 | 58.4 / 46.7 / 27.4 |
| `stream` | — | — | 52.0 / 46.9 / 38.4 |

Камин даёт ровно заданные 6 потрескиваний в секунду и вдвое более «пиковую»
огибающую, чем дождь; ветер — редкие длинные порывы; ручей ярче дождя наверху
и легче внизу.

Особенности, сделанные под ночное прослушивание:
- узкий динамический диапазон — нет моментов, которые будят;
- завал выше 12 кГц — убирает «звенящие» частоты;
- медленный спад громкости на −3.5 дБ за первые 45 минут;
- fade-in 20 с, fade-out 90 с — без резкого обрыва;
- пэды: смена аккорда раз в 20–40 с, отсутствие формы и кульминаций.

### `engine/calibrate.py` — громкость

Рендерит короткий ровный пробник, измеряет его через `loudnorm` и вычисляет
выходное усиление под целевые **−14 LUFS / −1 dBTP** (стандарт нормализации YouTube).
Без этого шага шум выходит на −5.9 LUFS с клиппингом на +3.4 dBTP.
`build.sh` вызывает калибровку автоматически.

### `engine/visuals.py` — видео

Процедурные кадры на numpy. Вся анимация задана синусами, периоды которых делят
длину петли нацело, поэтому **петля математически точная**: кадр N идентичен кадру 0.
Значит сегмент кодируется один раз и склеивается через `-c:v copy` — рендер 10 часов
стоит столько же кодирования, сколько 90 секунд.

Режимы: `rainglass` (дождь по стеклу с боке), `ember` (камин), `gradient`, `black`.
Палитра жёстко привязана к токенам бренда из `../global-sleep-brand/02-brand-and-visuals.md`.

Визуал процедурный, а не сгенерированный моделью, поэтому для него **не требуется
пометка synthetic content** и он не попадает под политику inauthentic content
как «шаблонный вывод генератора».

### `engine/build.sh` — сборка

`visuals.py` → сегмент → `calibrate.py` → `sleepaudio.py` → мультиплексирование.

```bash
./engine/build.sh --preset brown_noise --mode black    --hours 10 --out out/brown_10h.mp4
./engine/build.sh --preset ocean       --mode gradient --hours 8  --out out/ocean_8h.mp4
./engine/build.sh --preset rain_pad    --mode rainglass --hours 3 --seed 4471 --out out/rain_pad_3h.mp4
```

Ключи: `--loop` (длина петли, по умолчанию 90 с) · `--w/--h` · `--fps` · `--crf`
· `--abr` (битрейт аудио, по умолчанию 192k) · `--seed` (меняет и музыку, и
расположение боке) · `--lufs` · `--gain-db`.

Для шума и дождя `--abr 128k` прозрачен на слух и снимает около 200 МБ
с восьмичасового файла — заметно, если файл потом куда-то загружать.

## Измеренные показатели

| | Значение |
|---|---|
| Громкость на выходе | −13.9 LUFS, true peak −3.9 dBTP |
| Битрейт 1080p24 | ~740 кбит/с видео + 192 кбит/с аудио |
| Размер 3-часового файла | ~1.2 ГБ |
| Время рендера 3 ч (1 ядро) | ~25 мин (петля 11 мин + аудио 12 мин + мукс 2 мин) |
| Время рендера 8 ч | ~45 мин — растёт только аудио, видео не пересчитывается |

### `engine/thumbnail.py` — превью

Единая сетка из бренд-гайда: знак слева вверху, ярлык из одного-двух слов внизу,
длительность справа, акцентная линия по серии, затемняющий градиент.

```bash
python3 engine/thumbnail.py --title "DEEP SLEEP" --duration 8H \
        --accent sleep --bg assets/rain_1.png --out out/thumb.png
```

Акценты: `sleep` `rain` `nature` `ember` `noise` `focus` `gold`.
Без `--bg` фон рисуется процедурно.

Скрипт сам проверяет себя: уменьшает результат до 120 px — ширины карточки в ленте —
и печатает контраст подписи. Ниже 0.45 выдаёт предупреждение.

Текст рисуется через Pillow, а не через `drawtext`: переносимая сборка ffmpeg
собрана без freetype, и фильтра `drawtext` в ней просто нет.

**Ограничение по шрифту.** В бренд-гайде указаны Poppins / Jost Light, но
Google Fonts закрыт политикой egress, поэтому по умолчанию берётся DejaVu Sans.
Положите нужный `.ttf` и укажите его: `THUMB_FONT=/path/Jost-Light.ttf`.

### `engine/metadata.py` — локализованные метаданные

Генерирует заголовки, описания и теги на EN / ES / PT-BR / DE / JA для всего релиза.

```bash
python3 engine/metadata.py --release releases/batch-01.json --out releases/batch-01
```

На выходе — по файлу на видео, готовому к копированию, плюс `localizations.json`
в формате объекта `localizations` для YouTube Data API (`videos.update`).

Формулировки — **нативные поисковые запросы, а не переводы**. Машинный перевод
«Deep Sleep Music» на немецкий даёт «Tiefer Schlaf Musik», чего никто не ищет;
реальный запрос — **Einschlafmusik**. Каждая строка подобрана как фраза, которую
рынок действительно набирает.

В каждое описание автоматически вставляются заявление об оригинальности и
медицинский дисклеймер на нужном языке — без них видео публиковать нельзя.

### `releases/batch-01.json` — первые 10 видео

Десять запусков, у каждого **свой звуковой мир и свой набор кадров**: ни одна
дорожка и ни один кадр не переиспользуются, потому что именно это ищет политика
inauthentic content.

```bash
./engine/fetch_assets.sh                      # скачать кадры Higgsfield
./engine/render_release.sh releases/batch-01.json
```

Порядок: дождь 8ч · камин 8ч · океан 10ч · зимний ветер 8ч · лесной ручей 8ч ·
ночной город 3ч · космос 8ч · коричневый шум 10ч · розовый шум 10ч на чёрном экране ·
музыка для сна 3ч. По одному видео в день, два подряд одной темы не ставить.

Весь батч — ночная задача: примерно 25 минут на 3-часовое видео и 45 на 8-часовое.

### `engine/photoloop.sh` — фотореалистичный режим

Собирает бесшовную петлю из трёх неподвижных кадров:

```bash
./engine/build.sh --preset rain_window --mode photo \
  --photos assets/scene_a.png,assets/scene_b.png,assets/scene_c.png \
  --hours 3 --out out/rain_3h.mp4
```

Цепочка `A_body → B → C → A_head`: A_body начинается на X секунде зума сцены A,
A_head — это первые X секунд того же зума, поэтому последний кроссфейд приходит
ровно в тот кадр, с которого петля началась. Длина петли `3 × (scene − xfade)`,
по умолчанию 102 с.

Параметры: `--scene` (40 с) · `--xfade` (6 с) · `--zoom` (0.04, то есть 4 % за сцену).

**Проверено измерением.** Нулевой кадр против крайнего: средняя разница
**1.23/255**, пикселей с разницей >8 — **0.03 %**. Для сравнения, нулевой кадр
против середины петли: 12.58/255 и 42.7 % пикселей. То есть шов на порядок
слабее обычной межкадровой разницы и физически незаметен.

Яркостное «дыхание» намеренно не добавлено: его фаза не сходится на стыке и
давала бы ступеньку раз в петлю. Движение обеспечивают зум и кроссфейды.

## Ограничения, которые нужно знать

- Визуал стилизованный, а не фотореалистичный. Для фотореализма нужны кадры Higgsfield
  и нереализованный `--mode photo`.
- Видеодорожка не затухает в конце (аудио затухает). Затемнение потребовало бы
  перекодирования всего файла и съело бы выигрыш от `-c:v copy`.
- Рендер однопоточный. На многоядерной машине аудио и видео можно считать параллельно.
- `rain_pad` и `ocean_pad` тратят ~20 с на предрендер пэд-ячеек — это разовая
  стоимость, не зависящая от длины видео.
